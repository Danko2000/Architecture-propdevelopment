# Аудит информационной безопасности

Анализ и обоснование выбора разделов\
Выбранные разделы и почему:\
1. Управление доступом
   
Обоснование:\
Компания работает с двумя категориями пользователей: клиентами и собственниками.\
Есть проблема с изоляцией данных: пользователи видят чужие данные.\
Отсутствует единая политика доступа, особенно для внешних API (управляющие компании).\
Нет контроля за тем, какие данные получают партнёры.\
Риск: несанкционированный доступ, утечка персональных данных, нарушение 152-ФЗ. 

2. Безопасность данных
   
Обоснование:\
Компания обрабатывает персональные и финансовые данные (ФИО, паспорт, платежи, договоры).\
Данные передаются через незащищённые API с партнёрами.\
Нет классификации данных → все данные обрабатываются одинаково, включая ПДн.\
Планируется развитие BI/ML/AI-сервисов → требуется безопасное хранение и обработка больших объёмов данных.\
Риск: утечка ПДн, штрафы, невозможность масштабировать аналитику. 

3. Защита инфраструктуры
   
Обоснование:\
Используется гибридная инфраструктура (ЦОД + облако).\
Доступ извне осуществляется через firewall, но нет сегментации между доменами (продажи, ЖКУ, финансы).\
Нет упоминания о IDS/IPS, мониторинге, сканировании уязвимостей.\
Риск: компрометация одного сервиса → компрометация всей системы. 

4. Управление инцидентами
   
Обоснование:\
Компания реагирует на инциденты у конкурента — значит, осознаёт угрозу.\
Нет упоминания о SIEM, плане реагирования, учениях.\
Один специалист по ИБ → нет резерва и автоматизации.\
Риск: при реальном инциденте — потеря контроля, задержка реакции, репутационные и финансовые потери. 

6. Специфические аспекты — API и интеграции
   
Обоснование:\
Ключевая проблема: API партнёров не контролируются, передают ПДн, не имеют политик безопасности.\
Интеграции с госорганами — повышенный уровень критичности.\
Риск: внешние системы становятся вектором атаки.
